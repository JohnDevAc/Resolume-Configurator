## Recovery and remaining acceptance

Operation records remain under the selected composition directory's `Configurator Backups/<operation ID>`. The `Files[].Backup` entries point to `.configurator-<GUID>.original` files beside their respective destination. Keep these files until the configuration is accepted. A concurrent rename detected through the captured backup can already have replaced the active path: the operation reports a conflict and retains the displaced bytes for explicit recovery; it does not silently report success. Earlier successful distributed writes may remain after any later failure.

Failed saves may retain `.configurator-save-<GUID>.previous` beside the requested AVC; the error identifies the recovery path. A hard process/OS failure during save can also leave that file for manual recovery. A blocked close keeps ordinary operation supervision alive; forced termination cannot roll back API mutations already dispatched. Parent/worker leases apply to the current Windows user's configurator instances.

Physical Arena/NDI/Kiloview acceptance is still required for source naming, stable graph restoration, preset reuse and publication. Coarse timestamps and separate data/composition directories were emulated with ordinary temporary files; no physical FAT/SMB or second-volume acceptance is claimed. Operating-system sharing/atomic-replace support is required, and unsupported filesystems report a file error. Distributed job/Agent/Arena checks are not a transaction or a lock on external operators.

Compatibility remains Windows x64, Arena 7.27.x, schema-1 Job Configurator/local PC Agent, and N6/N60. The installer remains unsigned. PC NDI writes stay owned by PC Agent; no sibling APIs or deployment scopes changed.
