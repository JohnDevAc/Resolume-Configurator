**Findings, in priority order**

**1. P1 — Encoder matching can silently select a different device.**

In [SourceMatcher.cs:54](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/SourceMatcher.cs:54>), normalized prefix/substring matches are accepted automatically. The fixture demonstrated that an unavailable `TT-001` matches the only available source, `TT-0010`. Adding a real `TT-0010` encoder causes both rows to select that source. The UI labels the result “Matched,” and plan validation checks only whether a source token is present. The wrong feed can consequently be loaded throughout the composition. Require a full host/channel identity or an unambiguous token boundary; present fuzzy matches for review and flag duplicate source assignments. The existing decoder preset name-collision test does not cover encoder source matching.

**2. P1 — Decoder discovery and N60 verification do not establish the intended Arena host.**

[KiloviewDecoderPresetService.cs:348](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/KiloviewDecoderPresetService.cs:348>) chooses equally named senders by descending port. The N6 path does the same after excluding the decoder's own address. Neither receives the identity/address of the local Arena sender. With two Arena PCs advertising the same output name, the fixture selected the other PC solely because its port was higher. Separately, [line 382](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/KiloviewDecoderPresetService.cs:382>) accepts a matching N60 channel name **or** URL: a current stream from a different host was reported as successfully activated. Carry the selected production adapter/Arena sender identity into discovery and verification; reject ambiguous candidates and require the expected host as well as channel identity.

**3. P2 — Completion polling can cancel validation before a write is dispatched.**

[ResolumeApiClient.cs:299](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ResolumeApiClient.cs:299>) accepts an existing non-default thumbnail after approximately 250 ms. Its pending `PostAsync` also includes the asynchronous `BeforeMutation` guard. If that guard is still reading Job Configurator/PC Agent, cancelling the request cancels the guard; the resulting cancellation is swallowed and the method returns success. [ConnectClipAsync:341](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ResolumeApiClient.cs:341>) has the same behavior when a clip is already connected. Both were reproduced with a 1.2-second validation delay and **zero POST requests sent**. Await validation before starting completion polling, track dispatch separately, and propagate validation failure. Thumbnail completion also needs stronger evidence than an unchanged pre-existing image.

**4. P2 — Fast save/open responses bypass the advertised completion checks.**

[ResolumeApiClient.cs:164](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ResolumeApiClient.cs:164>) returns immediately when the save request completes successfully; [line 208](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ResolumeApiClient.cs:208>) does likewise for open. File freshness/settling and expected composition checks apply only while the HTTP response is pending. Fixtures returning HTTP 200 without creating a file or changing the composition were accepted. The initial backup path subsequently loads its file, which catches a missing backup, but final saves before a forced restart have no equivalent verification. Apply the same postcondition checks to both fast and stalled responses. For reloads, compare relevant graph identities/structure rather than counting repeated matching names.

**5. P2 — Filename sanitization does not make all generated paths usable.**

[ArenaPaths.cs:29](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ArenaPaths.cs:29>) replaces invalid characters and trims trailing dots/spaces, but leaves reserved device names and unbounded filename lengths. A 256-character job name passed `ValidatePlan`, then its generated `.avc` could not be written on this filesystem. `CON` also remains `CON`; Windows reserves such names even with extensions. See [Microsoft's filename rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file). Reserve space for `.avc`, ` - NDI Outputs.xml`, and backup suffixes; escape device names; use a short stable identity suffix when truncation or sanitization would otherwise create collisions. Validate the resulting paths before changing the composition. The manifest already enables long-path awareness, but that does not remove filename-component restrictions.

**6. P2 — Output file problems are detected after substantial Arena changes.**

The orchestrator starts renaming/resizing at [ArenaConfigurationOrchestrator.cs:43](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ArenaConfigurationOrchestrator.cs:43>), while preset-directory creation and preference processing happen at [line 222](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ArenaConfigurationOrchestrator.cs:222>). An unwritable preset/preferences directory, locked destination, or malformed existing `SimpleOutput.xml` therefore stops the run after the composition has been rebuilt. The malformed simple-output case can also occur after active Advanced Output has already been replaced. Preflight all destination directories, filenames and existing XML, and stage the generated documents before destructive composition work. Keep a record of each committed file and its backup for partial recovery. Preflight reduces these failures but cannot guarantee later network-drive availability or permissions.

**7. P2 — A lost restart-helper notification leaves the UI disabled indefinitely.**

[ArenaRestartService.cs:17](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/Services/ArenaRestartService.cs:17>) launches the helper and immediately releases its process handle. The main window keeps `_decoderHelperPending` set until a window message arrives at [MainWindow.xaml.cs:315](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/src/ResolumeConfigurator/MainWindow.xaml.cs:315>). There is no exit monitoring, operation deadline, durable result, or recovery action. An externally terminated helper, startup/runtime failure, or lost notification leaves Configure and Refresh disabled until the app is reopened. Monitor the helper process and use an operation ID plus a result file or named-pipe message. Distinguish successful completion, reported failure, and unexpected exit. Retain the full error in the operation log; currently helper error details are sent mainly through the window title.

**8. P2 — Installer packaging corrupts non-ASCII staging paths.**

[Build-Installer.ps1:108](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/scripts/Build-Installer.ps1:108>) writes the IExpress SED using ASCII, although it contains absolute paths under `%TEMP%`. An encoding check changed `C:\Users\José\...` to `C:\Users\Jos?\...`. The package then refers to a different/nonexistent payload location. This affects building the installer under such profiles; installation of an already-built package was not tested here. Use an IExpress-compatible encoding/path strategy, or explicitly validated ASCII staging, and test a non-ASCII Windows profile. Do not assume switching to UTF-8 alone establishes IExpress compatibility.

**9. P2 — Uninstall removes its registration before confirming file removal.**

[Uninstall-Local.ps1:9](</C:/Users/jligh/OneDrive/Documents/ChatGPT/Resolume Configurator/scripts/Uninstall-Local.ps1:9>) ignores the five-second exit-wait result, then deletes shortcuts and the Installed Apps entry before removing the installation directory at lines 17–22. A helper has no main window to close; if it remains active, locked executable files can make removal fail after registration is gone. Check every matching process and stop cleanly with an actionable message when one remains. Remove registration only after successful file removal. Installation also checks for the adjacent uninstaller only after copying the application; validate the complete payload first. These are static control-flow findings; the installed app was not uninstalled during this review.

**Directory and required-file assumptions**

The standard Documents layout is documented by [Resolume's directory list](https://resolume.com/index.php/support/en/directory-list). Using Windows `SpecialFolder.MyDocuments` is appropriate and already handles ordinary Documents redirection; it should not be replaced with a literal `C:\Users\...\Documents` path. The remaining assumptions need explicit validation and diagnostics:

**Optimization priorities**

1. **Reduce repeated validation overhead while retaining checks immediately before writes.** Every guard rereads health and the full job state, merges local credentials, reads Agent state, enumerates interfaces, creates an Agent HTTP client, and fetches status. The restart worker additionally performs an outer validation before methods that already have a `BeforeMutation` guard. Reuse the Agent transport; separate lightweight identity/readiness checks from credential loading; use operation-scoped immutable credentials only after validating the expected revision. Remove redundant outer checks only where the inner guard provides the same safety, including after internal waits. Measure request counts and timings before/after. The main clip workload scales as `3 × (decoders + 1) × encoders`, so repeated work grows quickly.

2. **Separate discovery timing from operational timing.** `TryReadApiAsync` gives the combined health + state exchange only 850 ms, including for the already-selected server on every write. That is a discovery optimization applied to normal operation. A slow but valid server or large state response becomes “unavailable” and can interrupt an active build. Keep fast bounded scan probes; provide a longer bounded operational deadline with precise timeout errors. Give decoder discovery/verification an overall wall-clock budget too: attempt counts multiplied by 45-second per-request timeouts can greatly exceed the apparent 30-second polling period.

3. **Reduce full XML and composition rereads.** Frame rate, router inputs and folded layers each load/save the same AVC independently. Apply these patches to one in-memory document, validate it, then replace once. During stalled save polling, inspect file metadata first and only parse XML after a stable change rather than parsing the full file every 100 ms. Reuse composition snapshots between operations that do not change structure, while retaining the final graph reread before resolving indices.

4. **Keep path/network work off frequent UI updates.** Every plan update resolves directories and performs `Directory.Exists` calls on the WPF thread. A redirected/unavailable Documents share can make simple edits sluggish. Resolve and validate paths once during asynchronous readiness and carry them in the immutable operation context. Avoid parallel structural Arena writes because group/layer indices change; independent decoder preflight is a better candidate for small bounded concurrency.

No fleet-scale performance benchmark or new physical-device acceptance run was performed. Existing transport reuse, bounded discovery workers, prepared source matching, local-state backup recovery, and job revision checks are useful foundations.
