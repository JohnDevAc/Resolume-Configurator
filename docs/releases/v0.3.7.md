# Resolume Arena Configurator 0.3.7

This release addresses all nine findings in the 7 September application audit. Automatic source matching now requires complete, unambiguous identities, and decoder selection verifies the Arena sender against the local PC Agent's production IPv4 address. N60 activation checks both the channel and sender URL.

Save, open and thumbnail operations verify completion after validation and dispatch. File destinations and XML are checked before composition edits; staged documents, atomic replacement, backups and operation records improve recovery. The parent monitors the restart helper and reports failed, missing or timed-out completion results.

Directory and executable overrides support custom Arena installations. Generated filenames handle reserved Windows names, collisions and length limits. Installation validates the complete payload manifest; installer staging supports Unicode user/output paths, and uninstall preserves registration if removal cannot finish. Reused HTTP connections and fewer repeated credential reads, XML writes and validation calls reduce overhead while retaining checks before mutation.

Compatibility: Windows 10/11 x64, Arena **7.27.x**, a configured local PC Agent with matching schema-1 state/status, and Kiloview **N6 or N60** decoders. Other Arena versions and decoder families fail preflight. Existing server/agent APIs and ownership of PC NDI settings are unchanged. Source installation payloads must be prepared with `scripts/Publish-Local.ps1` before running `Install-Local.ps1`.

Validation: **45/45 application regression checks**, **5/5 Windows PowerShell packaging checks**, and a Release build with warnings treated as errors passed. Installer generation was exercised with Unicode temporary and output paths. Physical Arena/NDI/Kiloview acceptance remains outstanding; stricter thumbnail verification can now time out where the old code accepted an unchanged thumbnail without completion evidence.
